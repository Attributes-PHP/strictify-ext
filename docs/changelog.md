# Changelog

All notable changes to Strictify are documented here, newest first. Install the pure-PHP library with `composer require attributes-php/strictify`, or the extension with `pie install attributes-php/strictify-ext`.

## Unreleased

### Added

- `CallException`, a `BaseException` subclass raised by `call()` when a required parameter has no dependency (`No value provided for parameter $x of f().`). It used to be a plain `Error`, so `catch (BaseException $e)` now covers the whole call path. Exceptions thrown inside the callable or inside a dependency container still propagate unwrapped.
- New built-in constraints ported from Respect/Validation: `Email`, `Url`, `Domain`, `Ip` (optional `v4`/`v6`), `Iban`, `Isbn`, `CreditCard` (Luhn), `Version` (semver), `MacAddress`, `Alnum`/`Alpha` (optional extra characters), `Digit`, `Xdigit`, `Slug`, `Base64`, `Json`, `HexRgbColor`, `Even`, `Odd`, `Positive`, `Negative`, `PrimeNumber`, `ContainsAny`. Each has its own default error message and translation key.
- `#[Url(...)]` gains optional `$protocol` and `$domain` arguments (`string|array|null`, both default `null`): `#[Url(protocol: 'https', domain: ['example.com', 'example.org'])]` rejects other schemes and hosts, compared in full and case-insensitively (ports and userinfo ignored; `https:`, `https://` and `https` are the same protocol). Rejections report the new `urlProtocol` (`Must be a URL using an allowed protocol: {expected}`) and `urlDomain` (`Must be a URL on an allowed domain: {expected}`) error keys.
- `#[Email(...)]` gains an optional `$domain` argument (`string|array|null`, default `null`): pass `domain: 'example.com'` or `domain: ['example.com', 'example.org']` to reject addresses on other domains, compared in full and case-insensitively against the part after the `@`. A rejected domain reports the new `emailDomain` error key (`Must be an email address on an allowed domain: {expected}`).
- `#[Sequence(sorted: ...)]` gains a `$sorted` option: `'asc'`/`'ASC'` or `'desc'`/`'DESC'` sorts the validated values and renumbers the keys `0, 1, 2, ...`; the default `null` keeps the input order. Replaces the `Sorted` constraint, which is dropped.
- `#[Sequence(...)]` and `#[Dict(...)]` now enforce their `$uniqueValues` flag (default `false`): with `uniqueValues: true` repeated elements are rejected with the new `uniqueValues` error key (`Must contain only unique values`), reported on the array property. `Dict::__construct()` accepts the flag as its third argument.
- New `Type::null` case / `T_NULL` constant (`MAY_BE_NULL`), usable as a `Union` arm — required when a nullable hint (e.g. `?string`) declares `#[Union(...)]` — and as a `Dict` key spec. `Dict` key specs now accept every PHP-castable key type (integer, string, float, boolean, null): `#[Dict(key: T_INT | T_STRING | T_NULL, of: ...)]`. Per [language.types.array](https://www.php.net/manual/en/language.types.array.php) the engine casts float/bool keys to int and null to `""`, so those arms match the post-cast key (`[2.0 => $v]` passes a `T_FLOAT` key spec as key `2`, `[null => $v]` passes a `T_NULL` spec as key `""`).
- `BaseModel::toDict()` gains a `useAlias` parameter: `toDict(bool $includeSensitive = false, bool $useAlias = false): array`. The output is keyed by the raw PHP property names by default; pass `useAlias: true` to key it by the resolved field names (`#[Alias]` / `aliasGenerator`, including each nested model's own generator), which round-trips through `validate()`.
- `#[ErrorMessage]` now accepts every key from the default error catalog as a named argument — `required`, `type`, `alphaDash`, `between`, `min`, `max`, `sequenceKeys`, ... — each defaulting to that key's default message, so any per-property template (constraint errors included) can be overridden. The `extra` key is discarded: extra inputs have no owning property and keep using the translator or the default message.
- Constraint attribute arguments are now validated once per field compile: arguments that make a constraint unsatisfiable or turn it into a no-op throw an `InvalidBaseModelException` naming the attribute, the model and the property — inverted or `NAN` numeric bounds, a negative or inverted `Size` range, an empty `In`/`StartsWith`/`EndsWith` list, an empty prefix or suffix, an empty `Email`/`Url` domain or protocol restriction, and a `Regex` pattern that does not compile (previously a PHP warning on every call).
- Two alias mistakes now throw `InvalidBaseModelException`: an empty `#[Alias('')]`, and two properties resolving to the same input key (`#[Alias('id')]` twice, or an alias generator collapsing `$aB` and `$a_b` onto `a_b`). Both used to produce fields that could never be satisfied or silently shadowed each other.
- A validation nesting depth guard: a payload that nests models more than 512 levels deep throws a catchable `MaxDepthException` (a new `BaseException` subclass) instead of exhausting the C stack. Siblings (array elements at one level) do not add depth, and the counter unwinds on every exit path, including a failing deep run.
- `validate()` and `call()` accept an `int $maxDepth` argument (default `512`) to override the nesting limit for one run — raise it for legitimately deep payloads or lower it to reject deep nesting earlier. A value below 1 throws a `ValueError`, and the exception message reports the limit that fired.

### Changed

- **BC note:** the error catalog keys are camelCase everywhere: the `#[ErrorMessage]` arguments and properties, and the key handed to `ErrorTranslator::set()` (`alphaDash`, `sequenceKeys`, `urlProtocol`, `uniqueValues`, ...). A translator registered under a snake_case key (`'sequence_keys'`) no longer matches; compare against the camelCase name instead.
- **BC note:** a malformed model declaration now always throws `InvalidBaseModelException` instead of a `ValueError` or `TypeError`. Attribute arguments rejected by a constructor signature (`#[Union(1.5)]`, `#[Min('fifteen')]`), unresolvable class arms, unsupported `Type` values, unsupported `Dict` key types, empty `Sequence`/`Dict` arguments, an invalid `Sequence(sorted:)`, a `DateTime` timezone argument and the constraint argument rules all keep their message and move onto the extension's exception hierarchy — `catch (BaseException $e)` now covers every malformed model. `ValueError` and `TypeError` remain for call arguments (`$maxDepth` below 1, the translator, `call()` dependencies) and for constructing an attribute object directly in userland.

- **BC note:** the `Attributes\Strictify` type constants are renamed with a `T_` prefix so they no longer collide with PHP's reserved type-hint keywords: `Attributes\Strictify\T_BOOL`, `T_INT`, `T_FLOAT`, `T_STRING`, `T_SEQUENCE`, `T_DICT`, `T_OBJECT` (previously `bool`, `int`, `float`, `string`, `sequence`, `dict`, `object`). Update `use const` imports and attribute arguments accordingly, e.g. `#[Union(T_INT, T_STRING)]` instead of `#[Union(int, string)]`.
- **BC note:** the `ErrorTranslator::set()` translator is now called as `fn (?string $key, string $message): ?string` — the stable key (`null` for custom `#[ErrorMessage]` values, whose text now arrives as `$message`) plus the default message template. Declare the first parameter nullable.
- **BC note:** `#[Union(...)]` declared directly on a union-typed property (e.g. `int|float`) must now contain the same type-hints as the native hint; a subset or an extra arm throws `InvalidBaseModelException` instead of narrowing/widening the accepted values. Nullable hints count `null` as a type-hint, so a `?string` property with `#[Union(...)]` must include `T_NULL` in the arms.
- **BC note:** the default error-message translator moved off `ModelConfigs` onto the new final class `Attributes\Strictify\ErrorTranslator`: `ErrorTranslator::set(callable $translator): void` and `ErrorTranslator::get(): ?callable`. `ModelConfigs::setDefaultErrorMessages()` / `ModelConfigs::getDefaultErrorMessages()` and the static `$defaultErrorMessages` property were removed.
- **BC note:** plain `toDict()` on models that use `#[Alias]` or `aliasGenerator` now returns property-name keys instead of alias keys. Pass `useAlias: true` for the previous behavior.
- **BC note:** `#[ModelConfigs]` is now inherited **only via the class hierarchy** (parent classes). A nested model (a `BaseModel` property of another model) no longer inherits the enclosing model's configs — `aliasGenerator`, `strict`, `extra`, the string normalizations and `stopAtFirstError` each resolve per model class. This changes the expected input keys of nested models (raw property names unless the nested class declares its own generator) and the nested keys in `toDict(useAlias: true)` output.
- **BC note:** `#[Sequence]` arrays now require **integer keys** — a string key reports `Must be integer` under that key's path — and are **sequential by default**: keys must be `0, 1, 2, ...` in order, otherwise a `sequenceKeys` error is reported. Pass `sequential: false` to allow any integer keys (gaps included); string keys stay rejected.
- `ModelConfigs` option values are type-checked instead of cast: a `bool` option only accepts `true`/`false` and a `?string` option only a string (at most 127 chars) or `null`, so `strict: 1` or `strToLower: 'yes'` throws `InvalidBaseModelException` rather than flipping a flag.
- `#[Sequence(sorted: ...)]` rejects a value outside `'asc'`/`'desc'`/`null` (case-insensitive) with an `InvalidBaseModelException` instead of silently leaving the array unsorted.
- `#[Sequence]`/`#[Dict]`/`#[Intersection]` on a non-array-like property — `string`, `int`, `object`, an intersection type without `array` — now throws `InvalidBaseModelException`; previously the rule missed those hints and the attribute was ignored.
- Validator fixes: `MultipleOf(0.0)` accepts `0.0` (not only the integer `0`); `DateTime` rejects a date that does not exist (`1994-02-30`, `2023-02-29`) instead of accepting the rolled-over date; `Iban` accepts either letter case; `Ulid` requires a first character in `0`-`7` (the 128-bit range); `Email` requires a top-level domain of at least two characters, like `Domain`; a `Regex` pattern containing a NUL byte is stored and matched in full.
- Constraints are skipped for an explicit `null`, exactly like a missing key (`#[Regex(...)] public ?string $name = null` accepts `['name' => null]`).
- Error messages render floats at full round-trip precision (`0.30000000000000004` instead of `0.3`), and `call()` names the parameter of an internal function in its `No value provided` messages.

## Recent history

- Mask `#[Sensitive]` properties as `***` in debug output (`var_dump()`, `print_r()`, `debug_zval_dump()`, and models inside exception traces); property access, `json_encode()`, `serialize()` etc. keep the real values.
- Restore string concatenation in `CallFunctionHooksUser::afterValidation`.
- `call()` respects `#[\SensitiveParameter]` on target parameters: missing dependencies are reported positionally and stack traces redact the argument.
- Add `#[Sensitive]` field attribute: `toDict()` omits it unless `includeSensitive: true`; the `{value}` error placeholder is redacted to `***`.
- `ModelConfigs::getDefaultErrorMessages()` static getter; `ModelConfigs` `extra` defaults to `null`, resolved per class; `'allow'` stores unknown keys as dynamic properties.
- Resolve a `null` `ModelConfigs` `extra` per nested model class at validation time.
